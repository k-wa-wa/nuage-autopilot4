# UI設計標準・デザインシステム原則

本プロジェクトの UI を構築する上でのデザイン哲学、デザイントークン体系、コンポーネント設計原則、および品質を保つためのガードレール（禁止事項）を定義する。

---

## 1. デザイン哲学（北極星）

- **「ミニマルで高密度な開発者コックピット × 洗練された触覚フィードバック（Liquid / Fluid）」**
- 派手な装飾や不要なグラデーションに頼らず、美しいタイポグラフィ、正確な余白、そして押した瞬間の心地よい物理フィードバック（弾性スプリング）で語るクラフトマンシップを追求する。
- スマホ（片手操作・スキマ時間での瞬時把握）とデスクトップ（一発俯瞰・集中操作）の双方で摩擦のない体験を提供する。

---

## 2. デザイントークン体系（Design Tokens）

すべてのデザイン値（色・余白・フォント・モーション・角丸）は CSS 変数（トークン）として宣言的に定義し、コンポーネント側での生値の直書きを禁止する。

### 2.1. カラーパレット（セマンティック定義）

本プロジェクトは**ダークテーマ専用**とし、ライトモードはサポートしない（ダークテーマを前提としたコントラスト・視認性設計に一本化する）。

- **ベースカラー**:
  - `--bg`: アプリケーション全体の背景色
  - `--fg`: 基本テキスト色
  - `--card`: カード・パネル背景色
  - `--line`: 境界線（ボーダー）色
  - `--muted`: 補助テキスト・不活性要素色
- **セマンティック・状態カラー**:
  - `--accent`: 主アクション・フォーカス・リンク色
  - `--warn`: エラー・警告・障害色
  - `--success`: 完了・成功インジケータ色
  - `--blocked`: 保留・待機インジケータ色
- **半透明（Alpha）パターンの基準階層**:
  透過率の直書き（`rgba`）による乱立を防ぐため、以下の3段階に集約してトークン化・適用する。
  - **弱（Subtle）**: バッジ・カード背景、不活性チップ
  - **中（Emphasis）**: ホバー時背景、選択中アイテム
  - **強（Border）**: 有色枠線、フォーカスリング背景

### 2.2. スペーシング（4px / 8px グリッドシステム）

余白（padding, margin, gap）は 4px / 8px の倍数に厳格に統一する。変則的な数値（5px, 7px, 13px等）は原則許容しない。

- `4px`: 極小（バッジ内部、アイコンとテキストの隙間）
- `8px`: 小（カード内要素間、チップ間隔、ボタン内パディング）
- `12px`: 中小（カードヘッダー、モーダル内セクション）
- `16px`: 中（コンテナパディング、グリッドギャップ）
- `20px〜24px`: 大（メイン領域パディング、モーダル外枠）

> **Note (暫定的な逸脱に関する注記)**:
> 現在のコードベースでは高密度バッジの上下余白等に `padding: 2px` や変則値が一部残存しているが、これらは暫定的な逸脱として扱う。新規実装では 4px / 8px 基準を遵守し、既存の 2px 等の整理・統一方針は今後のリファクタリングで検討する。

### 2.3. タイポグラフィ階層

- **フォントファミリ**:
  - 本文・UI: `"IBM Plex Sans", "IBM Plex Sans JP", ui-sans-serif, sans-serif`
  - コード・メタ情報: `"IBM Plex Mono", ui-monospace, monospace`
- **サイズ階層（5段階に制限）**:
  - `11px`: タグ、バッジ、メタデータ、タイムスタンプ
  - `12px`: 補助テキスト、補足リンク、小ボタン、コンテキストバー
  - `13px〜14px`: 本文、カードタイトル、チャットメッセージ、標準ボタン
  - `15px`: ヘッダータイトル、セクション見出し、モーダル見出し
  - `18px〜22px`: モーダル内クローズアイコン、重要数値

### 2.4. 角丸（Border Radius）階層

- `sm (4px)`: バッジ、タグ、小さなインジケータ
- `md (6px〜8px)`: 通常ボタン、カード、セレクト、入力欄
- `lg (12px〜16px)`: モーダルボックス、ボトムシート、Composer
- `full (9999px)`: ピル型チップ、丸型送信ボタン

### 2.5. モーション・触覚トークン（iOS Fluid Interaction）

ボタンやインタラクティブ要素の押し心地を統一するため、イージングと持続時間をトークン化する。

- **イージング**:
  - `--ease-spring`: 指を離したときの弾むスプリング復帰
  - `--ease-snappy`: 押した瞬間の素早い沈み込み
- **持続時間**:
  - `--duration-press`: 押下時の即時フィードバック
  - `--duration-release`: 復帰時のなめらかなスプリング
- **スケール**:
  - `--scale-button-active`: 標準ボタン・バッジ押下時の縮小比率
  - `--scale-icon-active`: アイコンボタン・閉じるボタン押下時の縮小比率

## 3. ガードレール（禁止事項・アンチパターン）

統一感を損なわないための厳格な制約：

1. **生の値（Magic Values）の直書き禁止**:
   - CSSに生カラーコード（`#3b82f6` や `rgba(...)`）を直書きしない。必ずセマンティックトークンを経由する。
   - ダークテーマ専用のため、生ホワイト（`#fff`）や生ブラック（`#000`）の直書きを避け、必ずセマンティック変数（`--fg`, `--bg`, `--card` 等）を使用する。
2. **ブラウザ標準の青枠・ハイライトの排除**:
   - モバイルWebKitのタップハイライト（`-webkit-tap-highlight-color: transparent`）を徹底する。
   - タップ時・マウスクリック時の青枠（`:focus:not(:focus-visible)`）を抑止し、キーボード操作時（`:focus-visible`）のみアクセシビリティを保つ。
   - モーダルオープン時の自動フォーカスによる青枠（×ボタンのアウトライン等）を許容しない。
3. **モバイルでの `:hover` 残留の禁止**:
   - ホバースタイル（色の変化や `transform`）は必ず `@media (hover: hover)` でラップし、タッチデバイスでタップ後にホバー状態が画面上に残らないようにする。
4. **長押しテキスト選択の誤発火禁止**:
   - ボタンやインタラクティブ要素には `user-select: none;` と `touch-action: manipulation;` を適用し、連打や長押しでテキスト選択枠を出さない。
5. **過剰な装飾の排除**:
   - 目的のないアニメーション、過度なグラデーション、意味のないドロップシャドウを避け、情報の視認性と読みやすさを最優先とする。
6. **iOS Safari フォーム自動ズームの防止**:
   - モバイル幅（`@media (max-width: 768px)`）での入力要素（`input`, `textarea`, `select`）は `font-size: 16px` 以上を維持する。16px 未満を指定すると iOS Safari がフォーカス時に画面を自動拡大し、レイアウトが崩れるため。

## 4. UIコンポーネントの基本設計原則（責任の分離）

- **Card**:
  - 状態とアクションの最小単位。
  - カード全体をクリックすると該当の GitHub Issue/PR に遷移する。
  - サブアクション（履歴モーダル表示、チャット調査開始）は独立したバッジボタンとして明確に分離する。
- **Modal**:
  - 補助的な詳細情報（エラー原因、エージェント履歴、システム情報）の表示に徹する。
